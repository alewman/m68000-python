# Contributing

Issues are the right place for bug reports, API discussion and proposed
changes; a disagreement with an oracle is an issue with the evidence
attached, not a pull request that changes the core.

For a pull request:

1. Keep the instruction core independent of machine and device policy; the
   host owns everything the [README](README.md)'s boundary gives it.
2. **Never change the core against the gate.** The pinned SingleStepTests
   corpus decides bus order, clocks and the stacked PC unless a source
   closer to silicon says otherwise; a rule [claims.md](docs/claims.md)
   lists as contested stays on the gate until real-hardware evidence
   decides it. A change that makes the gate fail is wrong or needs a new
   decision, in that order.
3. A core fix lands as a **failing test first**, in its own commit, then
   the fix. Add a focused test for any behaviour change: in
   `tests/test_coverage_gaps.py` when the manual decides it, in
   `tests/test_referee_evidence.py` when a referee run does; and rerun the
   whole gate.
4. A new or changed handler keeps the readability contract
   (`tests/test_readability.py`): its docstring starts with the Motorola
   name, ends with its sources in parentheses, and names what pins any rule
   the manuals do not give. The vocabulary:
   - sources: `PRM 4-116` (a page), `PRM Table 3-18`, `PRM 2.2` (a
     section), `UM 6.3.6`, `UM Figure 6-7`, `UM Table 8-12` or
     `UM Table 8-12: 20 clocks`, `UM Tables 8-2, 8-3`; several joined by
     `; `;
   - evidence: `SST MOVE.b/.w/.l` or `SST ILLEGAL_LINEA` (files of the
     gate corpus), `WinUAE run` (docs/referees.md), `flamewing` (the T1
     BCD tables).
5. Run `python -m pytest -q`, `python -m ruff check .` and
   `python -m ruff format --check .` (CI runs all three, plus the examples
   and a wheel build). With the corpus fetched, `pytest` includes the gate
   and the `step_clocks` claim; without it they skip.
6. Every number in a document is regenerated by the command the document
   names, never remembered; a claim names its oracle and the oracle's tier
   in the sentence that makes it.
7. Public API and lifecycle changes go under the right heading in
   `CHANGELOG.md` (**Breaking** with a one-line migration, before 1.0) and
   into [docs/api-stability.md](docs/api-stability.md).

Do not commit the corpora, ROMs, MAME traces, referee sources or builds,
caches, generated package artifacts or credentials.
